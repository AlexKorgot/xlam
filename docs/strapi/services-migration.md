# Перенос блока «Услуги» в Strapi

Статус: модели и данные подготовлены в ветке `strapi-integration`. Пять услуг и
общая фраза перенесены **черновиками** в локальную Strapi; ни одна запись не
опубликована. Сайт пока продолжает читать
`src/components/ui/ServicesSliderSection/services.data.ts`; публикация в Strapi
не влияет на него до следующего этапа. Production и VPS не менялись.

## Текущий источник и структура

Пять услуг идут в порядке `show`, `b2b`, `ads`, `branding`, `brand`. Карточки
показываются на `/` и `/main`. Подробное содержание открывается внутри модального
окна; отдельных маршрутов для услуг сейчас нет.

Collection Type **Service** хранит устойчивый `key`, `sortOrder`, текст карточки,
видео, постеры для двух размеров экрана, тексты подробного просмотра, фоновые
изображения, подписи CTA и упорядоченные пункты **Service Feature**. Для медиа
есть поля Media Library и URL-поля: при первом переносе используются URL
существующих файлов, позже редактор сможет выбрать медиа в Strapi. Сборка сайта
должна требовать хотя бы один доступный источник для каждого обязательного
изображения и проверять опубликованные данные.

Single Type **Services Section** хранит общую фразу под слайдером. Надпись
«ХЛАМ MEDIA» остаётся элементом дизайна в React. Действие кнопки, порядок
анимаций, прокрутка, размеры и расположение также остаются в коде сайта.

## Исходные медиа

`public/service-media/` содержит копии 20 текущих WebP-постеров и фонов с
понятными именами. Исходные файлы в `src/components/ui/ServicesSliderSection/assets/`
сохранены. При копировании сохранена фактическая привязка изображений:
например, карточка `b2b` использует исходные `3.*.webp`, а `ads` — `2.*.webp`.
Видео уже находятся в `public/video/`. URL этих файлов внесены в черновой
набор данных. Локальные файлы остаются доступными после статической сборки;
загрузку нового медиа через Strapi нужно будет связать с REG.RU S3 перед
публичным запуском CMS.

## Подготовка и импорт черновиков

`cms/data/services.seed.json` повторяет текущие тексты, порядок, привязки
медиа и четыре пункта каждой услуги. Скрипт сначала проверяет поля и наличие
всех локальных файлов, ничего не записывая в Strapi:

```sh
cd cms
node scripts/import-services.mjs
```

После резервного копирования локальной `cms/.tmp/local-check.db` черновики можно
создать без API-токена командой `node scripts/import-services.mjs --apply-local`.
Режим ограничен этой локальной базой SQLite. Повторный запуск пропускает уже
существующие записи и не перезаписывает их.

Для отдельно настроенной Strapi можно задать `CMS_BASE_URL` и ограниченный
`CMS_WRITE_TOKEN`, затем запустить `node scripts/import-services.mjs --apply`.
Для удалённого адреса дополнительно требуется явный флаг `--allow-remote`;
production требует отдельного разрешения. Токены, база и загруженные файлы не
хранятся в Git.

Локальный импорт проверен сравнением всех полей с исходным набором: пять
черновиков услуг, по четыре упорядоченных пункта у каждой и один черновик
общей фразы. Опубликованных услуг нет. Резервная копия базы находится только в
локальной `cms/.tmp/`.

После импорта следует вручную сверить пять карточек и подробных экранов в
админке. Публикация черновиков и подключение данных к статической сборке —
следующий этап.
