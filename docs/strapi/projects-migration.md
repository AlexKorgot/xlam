Статус: проектирование, без изменения кода сайта и production. Базовая ветка: `vps`, commit `16430519afe234d1e571869cc09c6fa8c2be38b2`. Разработка: `strapi-integration`.

## Что используется сейчас

- Источник: `src/components/cinematic_new/data.ts`; тип: `src/components/cinematic_new/types.ts`.
- Пять записей в текущем порядке: `mer-tv`, `shame-to-know`, `agritek-bio` («Выбор»), `nastolka`, `eshche-dumaem`.
- `CinematicVideoSlider.client.tsx` импортирует массив напрямую и предполагает, что хотя бы один проект существует: первый проект используется для предзагрузки, а активный выбирается по индексу.
- `SliderScene.ts` использует видео, мобильное видео, постер и позицию кадра. Слайдер показывает до двух изображений preview и до восьми услуг.
- Медиа проектов сейчас берутся из `public/cinematic_videos`, `public/cinematic_posters`, `public/cinematic_previews` через `publicAssetPath`. Существующий REG.RU S3 уже задан как базовый адрес для другой части медиа.
- `next.config.ts` использует `output: 'export'`. После внедрения опубликованные данные должны попадать в статический результат сборки, без запросов браузера к Strapi.

## Предлагаемая модель Projects

Collection Type **Project** с Draft & Publish. Поля редактируемого содержания:

- `key`: уникальный стабильный идентификатор. При импорте сохранить текущий `id`, включая `agritek-bio`; не переименовывать его автоматически и не использовать для создания нового маршрута.
- `sortOrder`: целое число для порядка слайдов; исходный порядок 10, 20, 30, 40, 50.
- `eyebrow`, `title`, `description`, `client`, `year`: короткие текстовые поля, кроме длинного описания.
- `tags`: упорядоченный список коротких текстовых меток.
- `video`, `mobileVideo` (необязательное), `poster`: ссылки на медиа. При внедрении выбрать единый способ хранения в Strapi/S3 и проверить доступность URL во время сборки.
- `openedTitleLead`, `openedTitleAccent`, `openedBody`, `openedSecondaryBody` (необязательное), `navLabel`: текст раскрытого проекта.
- `services`: упорядоченный список коротких текстовых меток.
- `previews`: повторяемый компонент **Project Preview** с изображением и обязательным `alt`; текущие два изображения каждого проекта сохранить в том же порядке.

Для `tags` и `services` нужен удобный редактируемый список строк, например повторяемый компонент с одним текстовым полем. Точный вид полей и связей закрепить при создании Strapi-проекта с учётом выбранной версии Community.

## Что остаётся в коде сайта

`accent`, `videoObjectPosition`, `thumbnailCount`, количество видимых preview/услуг, расположение, анимации, GSAP, Three.js, маршрутизация и адаптивное поведение относятся к представлению. Текущая позиция кадра у всех пяти проектов одинаковая: `[0.5, 0.58]`. При переводе данных адаптер сайта должен сохранять действующий вид и поведение. Число пустых миниатюр можно вычислять в адаптере; в текущем наборе у всех проектов есть preview.

## Порядок безопасного перехода

1. Создать модель Project и компонент Project Preview в отдельном Strapi-приложении, без подключения production.
2. Внести пять существующих проектов как черновики, сохранить текст, порядок и привязку медиа. Проверить неоднозначные исходные значения редакционно: у «Выбора» ключ `agritek-bio`, а поле `client` сейчас равно «шоу-подкаст». Не исправлять эти значения молча.
3. Подготовить на стороне сборки получение **только опубликованных** записей, валидацию обязательных полей, сортировку по `sortOrder` и преобразование в существующий `CinematicSlide`. Для массива из нуля проектов или ошибочного ответа CMS сборка должна завершаться ошибкой, а последняя опубликованная версия сайта оставаться доступной.
4. В CI получать данные из Strapi перед `next build`; секрет API хранить только в защищённых настройках окружения CI. Браузер посетителя получает только собранные файлы из `out`.
5. Проверить preview-сборку и сравнить пять проектов с текущим сайтом. Переключение production — отдельный этап и отдельное разрешение.

Публикация в Strapi в будущем должна запускать webhook → GitHub Actions → новую статическую сборку → безопасный versioned deploy. На этом этапе webhook, сервер, DNS, Nginx и production не меняются.
