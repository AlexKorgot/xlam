# Перенос блока «Команда» в Strapi

На первом этапе добавлен Collection Type **Team Member** и исходный набор из
девяти участников. Порядок, имена, должности и пути к портретам повторяют
`src/components/ui/TeamSection/team.data.ts`. Портреты уже находятся в
`public/persones/`; медиафайлы и production не изменялись.

`key` сохраняет устойчивую связь записи с участником в React, а `sortOrder`
задаёт порядок. Для изображения и необязательного видео доступны как URL-поле,
так и поле Media Library. Сначала будут использоваться существующие локальные
URL. Перед использованием новых загрузок вне локальной среды потребуется
настроить REG.RU S3 и проверить доступность медиа из статического сайта.

Исходные данные находятся в `cms/data/team-members.seed.json`. Скрипт
`cms/scripts/import-team-members.mjs` сначала проверяет обязательные поля,
уникальность ключей и порядка, а также наличие локальных портретов:

```sh
cd cms
node scripts/import-team-members.mjs
```

После создания резервной копии `cms/.tmp/local-check.db` режим `--apply-local`
создаёт отсутствующие черновики только в этой локальной базе. Повторный запуск
пропускает существующие записи и не перезаписывает редакторские изменения.
Все девять участников импортированы и опубликованы в **локальной** Strapi.
Перед публикацией сохранена резервная копия локальной базы. Поля и порядок
опубликованных записей сверены с исходным набором; Content API возвращает все
девять записей. Если заданы `STRAPI_URL` и `STRAPI_API_TOKEN`, страницы `/`,
`/main` и `/about` получают опубликованных участников из Strapi во время
статической сборки. Без этих переменных локальная сборка использует прежний
`team.data.ts`; в CI отсутствие переменных или опубликованных участников
останавливает сборку. Сборка также проверяет ключи, порядок, имена, должности,
портреты и наличие локальных файлов. Изменения Strapi видны на сайте после
новой сборки, без обращений браузера к CMS.

Локальная сборка с девятью опубликованными участниками прошла успешно; все
имена и портреты присутствуют в экспортированных трёх страницах. Следующий
этап — проверить отображение и переключение участников в браузере, а перед
выкладкой preview обеспечить доступ GitHub Actions к тестовой Strapi.

Прокрутка, бесконечный цикл, выбор активного участника, размеры плашек,
расположение портрета и анимация остаются в React/CSS. Заголовок и поясняющий
текст блока пока тоже остаются в коде; переносить их нужно отдельно как часть
редактируемых текстов страницы.
